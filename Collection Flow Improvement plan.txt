Collection Flow Improvement plan
Date: September 24, 2026
Status: Initial implementation completed locally on September 24, 2026.
Automated navigation/cache tests and emulator/hardware builds passed. The user
approved the visual result, including the view-switch loading correction.
Promoted locally to dist/LUNA-Release-Candidate.elf and dist/LUNA-FMCB-mc0.zip;

PURPOSE

Improve Collection browsing with precise single steps, continuous held movement,
predictable stopping, and a fast scan for large libraries. Preserve the existing
PSBBN-inspired cover stream and tune performance on real PS2 hardware.

1. CURRENT BEHAVIOR

- Collection uses a 420 ms animation, with held navigation advancing roughly
  every 180 ms. Each step carries the current offset into a new easing curve.
  Restarting that curve can interrupt velocity even when position is continuous.
- Cover loading and texture preparation run synchronously. A loading stall can
  interrupt motion regardless of how the animation curve is tuned.
- The shared cache holds ten covers and keeps the two nearest visual focus at
  full resolution. Adjacent navigation recycles entries; larger jumps currently
  rebuild the cache.
- Collection shares movement and artwork infrastructure with Orbit. New behavior
  must be scoped to Collection to avoid changing that view.

2. PROPOSED CONTROLS

Left/Right tap:
Move exactly one title. Begin immediately and settle softly without bouncing.
Keep Up/Down as equivalent controls for compatibility.

Left/Right hold:
After a short delay, accelerate into continuous browsing. Do not restart the
movement curve at every title boundary. Release to brake into the nearest cover
with minimal additional travel.

L1/R1 tap:
Keep the existing chunk-jump destination rules. Show a short directional
transition instead of animating through every skipped game.

L1/R1 hold:
Enter fast scan after approximately 450 ms. Start with the normal chunk jump on
press, then accelerate scanning if still held. Releasing must not add another
chunk jump. Settle onto a clearly identified cover.

L2/R2:
Keep existing chunk-jump behavior in the first version. Alphabet-group jumps are
an optional later addition, only when the active list is alphabetically sorted.
Do not silently introduce this remapping as part of the initial implementation.

Conflicting inputs:
Opposite directions held together brake to a stop. Direction reversal cancels
the old destination and smoothly changes velocity. Shoulder navigation takes
priority over directional navigation when both are held.

3. MOVEMENT IMPLEMENTATION

Add Collection-specific navigation state and pure update helpers in
nhddl/include/ui/navigation.h and nhddl/src/ui/navigation.c.

Track continuous position, velocity, destination, held direction, elapsed hold
time, and movement mode. Suggested modes: idle, single step, continuous browse,
chunk jump, fast scan, and settling.

Use elapsed milliseconds rather than frame-count repeats so PAL and NTSC have
matching navigation speed. Preserve position and velocity when new input arrives.
Use bounded time steps and safe arithmetic to prevent a long loading pause from
causing a large catch-up jump. Rebase coordinates periodically during wrapping
so prolonged scrolling cannot overflow the position representation.

Keep visual position separate from the settled selection, but derive the counter,
launch target, and options target from one consistent visible-focus calculation.
For a tap, finish the requested one-title move even if the button is released
early. For continuous browsing, choose a nearby landing cover without backing
across a title boundary unexpectedly. Fast scan may need stronger braking.

Integrate this state in nhddl/src/ui/gui.c before its generic repeat filtering.
Read button press, hold, and release every frame. Consume Collection navigation
there so the old input path cannot produce duplicate steps.

Cross or Triangle during motion must resolve the currently focused game and
cancel movement before launching or opening options. Confirm that curTarget and
the cover passed to the launch screen belong to that same game. If matching art
is unavailable, use the existing fallback rather than a different game's cover.

Reset movement and pending artwork requests when switching views, changing the
Collection/Favorites filter, or rebuilding the title list. Keep Circle's existing
immediate view switch. Do not restore the reverted Classic-to-PSBBN transition.

4. VISUAL IMPROVEMENTS

Update nhddl/src/ui/view_collection.c and its declaration in
nhddl/include/ui/views.h to accept the Collection movement information it needs.

- Derive cover position, scale, and brightness from the same continuous position.
- Blend focus emphasis between neighboring covers without discrete flashes.
- Keep the existing composition at normal speed and when stopped.
- At higher speed, gradually reduce outgoing cover enlargement and slightly
  compress spacing. Restore both smoothly during braking.
- Keep the background and Collection/Favorites labels steady.
- Avoid bounce, expensive blur, duplicated cover trails, or additional large
  textures in the first version.
- During fast scan, show a temporary position counter and, when alphabetically
  sorted, a first-letter indicator. Hide the letter indicator after settling.
  Keep the normal position counter visible. Preserve Collection's current choice
  to omit a permanent game-title label above the cover.
- Add a compact hint for shoulder-button fast scan without crowding the footer.

5. ARTWORK AND FRAME PACING

Update nhddl/src/ui/art_cache.c and nhddl/include/ui/art_cache.h as needed.

First measure file reading, decoding, thumbnail preparation, texture promotion,
and frame duration separately. Scheduling one load per frame does not make a
synchronous decode nonblocking, so use measurements to choose the loading method.

Prioritize the focused cover, the approaching cover, then covers ahead of travel.
Retain nearby covers behind the focus for reversals. Reuse entries by title
identity and invalidate obsolete requests after jumps, reversals, or filtering.
Preserve the current limit of two full-resolution resident covers unless measured
memory headroom justifies a separate change.

During fast scan, use available thumbnails and consistent placeholders instead
of decoding full artwork for every passed title. Large jumps should prioritize
the destination and fill its neighbors incrementally rather than synchronously
rebuilding all ten entries before drawing.

Keep memory bounded independently of library size. If synchronous loading still
causes visible stalls, evaluate prepared thumbnail assets or staged loading as a
separate implementation step. Do not promise hitch-free motion until tested.

6. INITIAL TUNING VALUES

These are starting points for testing, not final requirements:

- Single-cover animation: 280-340 ms.
- Directional hold delay: 250-300 ms.
- Continuous browsing: accelerate from about 3 to 6 titles per second.
- Shoulder fast-scan threshold: about 450 ms.
- Fast scan: start around 10 titles per second; raise only after profiling.
- Release settle: aim for 120-180 ms with no more than one additional title of
  travel. Lower the speed limit if this cannot be achieved cleanly.
- Temporary scan indicator: fade out about 400 ms after settling.

Keep tuning constants together. Small libraries should cap speed and avoid
cycling through the entire collection repeatedly on a brief hold.

7. IMPLEMENTATION ORDER

Phase 1: Record current frame timing and artwork costs. Add Collection movement
state, precise taps, continuous holds, reversal, and predictable settling.

Phase 2: Integrate destination-first artwork loading and cache reuse. Verify
memory usage and responsiveness before increasing scrolling speed.

Phase 3: Add shoulder-button fast scan, chunk-jump transitions, and temporary
navigation indicators. Ensure landing, launch, and options select the same game.

Phase 4: Tune scale, spacing, and focus emphasis across speeds. Validate on PAL,
NTSC, the configured emulator, and real PS2 hardware.

Optional later phase: Add alphabet-group navigation after deciding its button
mapping and rules for numbers, punctuation, and non-Latin titles.

8. VALIDATION AND ACCEPTANCE

Extend nhddl/tests/test_navigation.c with deterministic checks for:

- One title per tap, including rapid repeated taps.
- Continuous acceleration without resetting velocity at title boundaries.
- Predictable release, reversal, and simultaneous opposite inputs.
- Shoulder tap versus hold, with no duplicate jump on release.
- Equivalent motion under different frame intervals and safe long-frame handling.
- Empty, one-title, two-title, wrapped, and filtered collections.
- Consistent focused title for the counter, launch, and options.

Run the existing host tests with nhddl/tests/run-host-tests.sh from nhddl in a
compatible shell. Then rebuild using the documented emulator build before any
interactive source-change test. Confirm luna.elf is newer than edited sources.

Use only emulation/pcsx2-luna-isolated/pcsx2-qt.exe with the project's portable
profile and direct-ELF arguments described in AGENTS.md and EMULATION.md. Verify
boot log markers and user-visible window state separately.

Manually test short taps, long holds, rapid reversals, chunk jumps, release from
maximum speed, missing art, cold-cache browsing, Favorites, and launching during
motion. Compare cold and warm artwork performance on real hardware. Check that
Classic, Grid, and Orbit retain their existing behavior.

Completion criteria:
Single taps are precise; held motion does not repeatedly hesitate; release lands
predictably; reversals do not snap; artwork never displays under the wrong title;
memory stays bounded; and fast scanning is useful on a large library without
making small collections difficult to control. Record actual frame-time and
loading measurements before declaring the performance work complete.

9. LOCAL IMPLEMENTATION RECORD

Implemented Collection-specific time-based motion, precise taps, accelerated
holds, bounded stopping, faster braking on reversal, shoulder chunk jumps, and
L1/R1 fast scan. Added speed-dependent cover scaling/spacing, a temporary scan
letter, and a footer control hint. Launch and options resolve the visible focus.

Collection now remaps cached artwork by title, avoids duplicate entries in small
libraries, loads at most one missing cover per frame, prioritizes focus and the
travel direction, and suspends new decoding during shoulder fast scanning.
Ordinary moving prefetch is spaced by at least 90 ms. These synchronous reads
can still stall a frame; no hitch-free hardware performance claim is made.

Automated checks cover rapid taps, continuous velocity, reversal, scan release,
all sub-cover release positions at maximum speed, wrapping, small/empty lists,
cache layout, differing frame intervals, timer wrap, and long-frame recovery.
The existing tests for other views also pass.

View-switch loading correction:
The shared cover cache now retains decoded pixels while Classic or Grid is
active, releasing its VRAM so those views have room to draw. Returning to a warm
Collection reuses the decoded covers and thumbnails. Collection entry completes
any missing slots before the first frame instead of showing incremental pop-in.
Filtering invalidates the cache to prevent title/rank mismatches. Host regression
tests verify zero new PNG decodes on warm revisits, identity after shared-view
navigation, missing-art handling, filter changes, and the two-full-cover VRAM
limit. The cache remains bounded to ten decoded covers.
